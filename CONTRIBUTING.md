# Contributing to document_scanner

Rules and commands for anyone changing this repository.

## Before you start
1. Read the README and the decisions in `docs/adr` first. Keep each change focused on one thing.
2. Re-verify library, plugin and GitHub Action versions against official sources before adding or bumping any
   dependency. Do not copy versions from memory.

## Hard rules
- No real data, real personal documents, real patient data or secrets. Synthetic data only.
- Never commit: keystores, `google-services.json`, `local.properties`, `.env`, `.idea/`, build output.
- Clean-room project: no code, schemas, names or data from any employer.
- Do not publish artifacts anywhere (Maven, stores). Release automation only through the documented workflows.
- CI workflows: least-privilege `permissions`, `concurrency` with cancel-in-progress, never `pull_request_target`, pin or
  version-check third-party actions.
- The manifest must never declare `INTERNET`. No telemetry.

## Architecture rules
- `domain` is pure Kotlin (no Android, Compose or Room).
- `vision` hides the C++/JNI code behind Kotlin interfaces that use domain types; keep a fake for tests.
- `feature-*` modules depend on `domain` and `core:*`; no feature-to-feature dependencies; `app` is the only composition root.
- AppFunctions code is isolated in its module, guarded for API 36+, feature-flagged and off by default.
- Dispatchers are injected; camera analysis drops frames (`STRATEGY_KEEP_ONLY_LATEST`), it never queues them.
- UI text lives in string resources (English, German, French, Portuguese, Spanish); view models hold string
  resource ids, never display text. The app has a light theme only.

## Build and test commands
The Gradle wrapper (9.8.0) is committed: use `./gradlew`. Convention plugins live in `build-logic/`.
```
./gradlew ktlintFormat                # ktlint is strict (ktlint_official): format first, then check
./gradlew ktlintCheck detekt lint     # style, static analysis, Android lint
./gradlew check                       # unit + screenshot tests, Kover gates (domain 90%, overall 75%), no-INTERNET gate
./gradlew :app:assembleDebug          # debug APK; then: bash tools/check_apk.sh <apk>
./gradlew testDebugUnitTest -Proborazzi.record   # re-record screenshot baselines after an intended UI change
./gradlew connectedDebugAndroidTest   # instrumented tests on a running emulator (native code, OCR, PDF, Compose)
./gradlew :appfunctions:pixel6api37DebugAndroidTest   # Android 17 managed device (slow first boot, may time out once)
```
Easy to trip over:
- Instrumented tests use fixtures from `fixtures/synthetic` (generated by `tools/generate_synthetic.py`).
- Compose instrumented tests need Espresso 3.7+ to run on Android 17.
- AppFunctions only index on Android 17 images so far; see `docs/adr/008-appfunctions.md`.
- The merged manifest must stay free of `INTERNET` (ML Kit adds it; the app manifest removes it).

## Working style
- Small commits with clear messages; one logical change per commit.
- Tests accompany logic changes (`runTest`, Turbine for Flows). Inject dispatchers and clocks.
- Record decisions as ADRs in `docs/adr/`.
- Say exactly what was run and the result; if something failed or was skipped, say so.
